# SNN 加速器实验结果记录

本文档用于记录工程推进过程中由仿真截图得到的关键实验数据。后续撰写论文、简历或答辩材料时，可以把这里的数据整理成对比表格和实验分析。

## 1. 当前主路径配置

当前较稳定的一组仿真结果对应的加速器模式如下：

```text
conv_lif       = 4-core sparse
aer_fc         = block mask
current_buffer = pingpong
```

该配置表示：

- 卷积层输出电流通过 current buffer 缓存。
- 卷积后 LIF 层采用 4 核稀疏状态更新结构。
- 后级全连接层采用 Block-Mask AER 事件输入。
- 电流缓存边界已经改为 ping-pong buffer 结构，为后续跨时间步流水预留基础。

## 3. 端到端周期统计

最新稳定截图中的端到端周期数据如下：

```text
total_cycles      = 58960
actual_time_steps = 52
early_stop        = 1
perf_valid        = 1
```

含义说明：

- `total_cycles` 表示单张图像从启动到输出预测结果所经历的总周期数。
- `actual_time_steps` 表示实际执行的 SNN 时间步数。
- `early_stop = 1` 表示输出层早停逻辑生效，未完整执行最大时间步。
- `perf_valid = 1` 表示性能统计结果有效。

如果按 125 MHz 时钟估算，单张图推理延迟约为：

```text
58960 / 125 MHz = 0.47168 ms
```

## 4. 分阶段周期统计

当前截图中记录到的主要阶段周期如下：

```text
last_conv      = 787
total_conv     = 40924
last_conv_lif  = 212

```

这些数据可用于分析不同阶段在总推理周期中的占比：

- `conv` 阶段仍然是主要周期来源。
- `conv_lif` 经过稀疏扫描和多核划分后，单时间步处理周期明显低于完整 1568 地址扫描。
- `aer_fc` 经过 Block-Mask AER 后，最后一个时间步全连接事件处理周期为 137。

## 5. 卷积后 LIF 稀疏更新统计

当前稳定截图中的稀疏更新统计如下：

```text
last_conv_lif_skip   = 1153
last_conv_lif_update = 415
total_conv_lif_skip  = 60226
total_conv_lif_update= 21310
```

含义说明：

- `skip` 表示该地址在当前时间步不需要访问或更新膜电位状态。
- `update` 表示该地址需要进行 LIF 状态更新。
- 稀疏更新机制减少了大量无效神经元状态访问，可用于体现 SNN 稀疏性带来的存储访问优化。

最后一个时间步中，跳过比例约为：

```text
1153 / (1153 + 415) = 73.53%
```

全部已执行时间步中，跳过比例约为：

```text
60226 / (60226 + 21310) = 73.86%
```

## 6. AER 事件统计

当前稳定截图中的普通 AER 事件统计如下：

```text
total_aer_events = 9614
last_aer_events  = 192
```

含义说明：

- `total_aer_events` 表示整个推理过程中卷积后 LIF 层产生的有效脉冲事件总数。
- `last_aer_events` 表示最后一个时间步产生的有效事件数。
- 与直接传输完整 1568bit spike vector 相比，AER 形式只传输有效事件地址，更适合稀疏脉冲特征图。

## 7. Block-Mask AER 压缩统计

截图中统计了不同 block 大小下，普通事件可合并成多少个 block 包：

```text

```

对应压缩率为：

```text
block16 compression = 73%

```

```text
last_events = 192
last_pkt16  = 54
last_pkt32  = 37
last_pkt64  = 20
```

这组数据说明，Block-Mask AER 可以显著减少事件包数量，降低后级事件控制开销。

## 8. group4 权重读取优化统计

当前 Block-Mask AER 全连接层利用 FC 权重 BRAM 的 64bit 数据宽度，一个地址中包含 4 个 16bit 权重。group4 统计如下：

```text
group4_reads_total = 4314
group4_reads_last  = 88
weight_read_reduce_group4 = 56%
```

含义说明：

- 普通 AER 每个 spike 事件通常对应一次权重读取。
- Block-Mask AER 将同一 4 权重组内的多个 spike 合并处理。
- 当 group4 内存在多个有效 spike 时，可以用一次 64bit BRAM 读取完成多个权重贡献累加。

该结果可作为 Block-Mask AER 不仅压缩事件包数量，也减少 FC 权重读取次数的实验依据。

## 9. 多核 LIF 负载分布观察

在 4-core sparse conv LIF 结构下，曾观察到如下负载分布：

```text
core_fifo_max_count = {42, 52, 2, 2}
core_event_count    = {88, 99, 25, 16}
```

该结果说明：

- 不同 core 的事件负载存在明显不均衡。
- 负载不均衡主要与当前图像样本、卷积输出通道活跃分布以及地址划分方式有关。
- 该数据可作为后续讨论多核分区、仲裁策略和负载均衡局限性的依据。

## 10. 定点动态范围观察

当前工程中：

```text
weight format        = signed Q4.12
current/membrane     = signed Q14.12
```

对当前测试样本进行过一次 Python 等效动态范围统计，得到大致结果：

```text
conv_current_abs_max        ≈ 18.58
conv_lif_membrane_abs_max   ≈ 9.29
fc_current_abs_max          ≈ 85.02
output_lif_membrane_abs_max ≈ 79.79
```

Q14.12 的理论范围约为：

```text
[-8192, 8192)
```

因此当前样本并未充分利用 Q14.12 的整数动态范围。该结果可作为后续位宽压缩或定点格式优化的预研依据，但在正式修改 RTL 前，应继续用更多样本或硬件 TB 统计验证。

## 11. 后续论文可展开方向

根据目前已经获得的实验数据，论文中可以重点展开以下实验分析：

- 稀疏 LIF 状态更新对膜电位 RAM 访问次数的减少效果。
- AER 与 Block-Mask AER 对事件包数量的压缩效果。
- group4 权重读取复用对 FC 权重 BRAM 访问次数的减少效果。
- 4-core sparse LIF 的并行处理效果与负载不均衡现象。
- 当前定点格式动态范围利用率与后续位宽压缩空间。
- ping-pong current buffer 对后续跨时间步流水架构的支撑作用。
